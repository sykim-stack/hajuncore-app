# 상품 운영 워크플로 V2 제안

> **작성일:** 2026-09-12
> **상태:** 다음 구현 기준 제안
> **목적:** AI의 현시점 상품 추천에서 실제 판매 시작까지의 의사결정 순서를 HajunAI 화면과 메시지 흐름에 반영한다.

## 1. 핵심 결론

현재 상품검증 MVP는 **온채널 상품을 먼저 캡처한 뒤 네이버를 조사하는 구조**다. 실제 운영 흐름은 반대로 시작해야 한다. 먼저 AI가 현재 시장·시즌·사용자 조건에 맞는 상품 기회를 제안하고, 사람이 공급처에서 후보를 찾은 뒤 네이버 데이터를 비교해야 한다.

권장 표준 흐름은 다음과 같다.

```text
AI 상품 추천
  ↓
공급처 검색·후보 저장
  ↓
네이버 시장조사
  ↓
상품 품질·수익성 결정
  ↓
상품명·썸네일·상세 이미지 재작성
  ↓
사람 최종 승인
  ↓
판매 시작
```

이 흐름에서 **AI 추천은 탐색의 시작점**이고, **사람 최종 승인은 판매 시작의 조건**이다. AI가 추천했다는 사실만으로 상품을 승인하지 않는다.

## 2. 단계별 정의

| 단계 | 목적 | 입력 | 출력 | 결정권 |
|---|---|---|---|---|
| AI 상품 추천 | 현재 시점에 시도할 상품 기회 발굴 | 계절, 트렌드, 고객, 목표 마진, 판매 채널 | 추천 상품군·검색어·선정 이유 | AI 제안, 사람 선택 |
| 공급처 검색·저장 | 온채널 등에서 실제 공급 가능한 후보 확인 | AI 추천 키워드 | 공급처 원문, 공급가, 배송비, 상품코드 | 사람 |
| 네이버 시장조사 | 소비자 수요와 경쟁 상황 확인 | 공급처 후보, 상품명, 검색어 | 경쟁 가격, 리뷰, 평점, 키워드, 경쟁 이미지 | AI 분석 보조, 사람 판단 |
| 품질·수익성 결정 | 판매할 가치가 있는지 판단 | 공급처 자료 + 시장조사 | 통과·보류·반려 및 이유 | 사람 |
| 콘텐츠 재작성 | 판매 가능한 상품 페이지 준비 | 통과 상품, 원문 이미지, 조사 결과 | 상품명, 썸네일, 상세 이미지, 설명 초안 | AI 작성, 사람 검수 |
| 최종 승인 | 실제 판매 시작 전 확인 | 검증 결과 + 콘텐츠 | 승인 결정 | 사람 |
| 판매 시작 | 승인 상품을 판매 채널에 반영 | 최종 승인 상품 | 판매 시작 기록, 채널 URL | 사람 또는 명시적 실행 |

## 3. HajunAI 방 구조 제안

현재의 네 방만으로도 구현할 수 있지만, 실제 운영 순서를 명확히 하려면 **추천 단계와 콘텐츠 제작 단계를 별도 방으로 분리하는 것이 좋다.** 상품 원문을 방마다 복제하지 않고 메시지 참조로 연결한다.

```text
상품검증마당
├── 상품추천방       신규: AI 추천과 사람의 후보 선택
├── 상품발굴방       기존: 온채널 등 공급처 원문 저장
├── 시장조사방       기존: 네이버 조사 저장
├── 검증방           기존: 품질·수익성·판매 여부 결정
├── 콘텐츠제작방     신규: 상품명·썸네일·이미지·상세 설명 작성
└── 승인상품방       기존: 최종 승인과 판매 시작 준비
```

방을 추가하지 않고 단계만 먼저 운영하려면 다음 임시 매핑을 사용할 수 있다.

| 실제 단계 | 임시 방 |
|---|---|
| AI 상품 추천 | 상품발굴방 상단 또는 별도 추천 메시지 |
| 공급처 검색·저장 | 상품발굴방 |
| 네이버 시장조사 | 시장조사방 |
| 품질·수익성 결정 | 검증방 |
| 콘텐츠 재작성 | 검증방의 `work_result` 또는 별도 콘텐츠 메시지 |
| 최종 승인·판매 시작 | 승인상품방 |

그러나 장기적으로는 추천과 콘텐츠 제작을 별도 방으로 분리해야 메시지의 역할이 혼합되지 않는다.

## 4. 메시지 연결 계약

모든 단계는 원문 복제가 아니라 `ref_ids`로 앞 단계의 근거를 연결한다.

```text
AI 추천 메시지
  ↓ ref_ids 없음 또는 트렌드 자료 참조
공급처 후보 메시지
  ↓ ref_ids: AI 추천 메시지 ID
네이버 조사 메시지
  ↓ ref_ids: 공급처 후보 메시지 ID
검증 결정 메시지
  ↓ ref_ids: 공급처 후보 + 시장조사 메시지 ID
콘텐츠 제작 메시지
  ↓ ref_ids: 검증 결정 메시지 ID
승인 메시지
  ↓ ref_ids: 검증 결정 + 콘텐츠 제작 메시지 ID
판매 시작 메시지
  ↓ ref_ids: 승인 메시지 ID
```

상품 식별자는 공급처 후보가 생기는 시점부터 만든다.

```text
internal_code = source + ":" + source_product_code
```

AI 추천 단계에는 아직 공급처 상품코드가 없을 수 있으므로 추천 메시지는 `recommendation_id` 또는 추천 제목·검색어를 metadata에 저장한다. 공급처 후보가 저장되면 그 후보와 추천 메시지를 `ref_ids`로 연결한다.

## 5. AI 추천 단계의 최소 출력

AI 추천은 단순히 상품명을 반환하지 않는다. 다음 항목을 포함해야 한다.

```json
{
  "recommendation_title": "차량용 QR 주차번호판",
  "why_now": "현재 수요와 계절성에 대한 설명",
  "target_customer": "주차 공간을 공유하는 차량 보유자",
  "search_keywords": ["차량용 주차번호판", "QR 주차번호판"],
  "expected_price_band": "8,000~20,000원",
  "risk_flags": ["경쟁 상품 다수", "디자인 차별화 필요"],
  "next_action": "온채널에서 공급가와 배송비를 확인"
}
```

추천 결과의 `why_now`, `risk_flags`, `next_action`은 이후 공급처 검색과 검증 결과를 비교하는 기준으로 사용한다.

## 6. 품질·콘텐츠 결정 기준

검증방에서 최소한 다음 항목을 확인해야 한다.

- 공급가와 배송비를 포함한 총원가
- 예상 판매가와 목표 마진
- 네이버 경쟁 상품 가격대
- 리뷰 수와 평점
- 상품의 차별성
- 공급처 원문의 품질
- 이미지 사용 가능성 및 저작권 위험
- 상품명과 검색 키워드의 적합성
- 배송·반품·품질 위험

품질 결정은 다음 중 하나의 새 결정 메시지로 기록한다.

```text
통과: 콘텐츠 제작으로 진행
보류: 추가 조사 또는 공급처 확인 필요
반려: 판매하지 않음
```

기존 메시지를 수정하지 않고 새 결정 메시지를 append한다.

콘텐츠 제작 단계에서는 다음 결과를 별도 메시지로 남긴다.

- 최종 상품명 후보
- 썸네일 문구와 구성안
- 상세 이미지 재작성 지시 또는 결과물 참조
- 상품 설명 초안
- 금지 표현과 주의사항

콘텐츠 결과가 작성되었다고 해서 자동 승인으로 처리하지 않는다.

## 7. 판매 시작의 경계

승인상품방은 판매 시작 직전의 운영 큐다. 판매 시작은 별도의 명시적 행동으로 기록해야 한다.

```text
사람 최종 승인
  ↓
판매 시작 버튼 또는 판매 시작 메시지
  ↓
채널 등록·게시 결과 기록
```

초기에는 카페24·스마트스토어·온채널 등의 외부 등록을 자동화하지 않고, 사람이 등록한 뒤 채널 URL과 등록 결과를 `판매 시작` 메시지에 기록하는 방식이 안전하다.

## 8. 현재 구현과의 차이

| 항목 | 현재 MVP | V2 방향 |
|---|---|---|
| 시작점 | 온채널 수동 캡처 | AI 현시점 상품 추천 |
| 공급처 저장 | 구현됨 | AI 추천을 `ref_ids`로 연결 |
| 네이버 조사 | 페이지 전체 수동 저장 | 후보별 조사 연결을 단계적으로 개선 |
| 검증 | 참조 메시지와 자유 텍스트 | 품질·마진·위험 체크리스트 |
| 콘텐츠 제작 | 별도 흐름 없음 | 상품명·썸네일·이미지 제작 단계 추가 |
| 승인 | 사람 확인 후 승인상품방 append | 최종 콘텐츠 검수 후 판매 시작 |
| 판매 시작 | 미구현 | 명시적 판매 시작 기록 |

## 9. 구현 우선순위

1. **AI 추천 메시지 계약과 화면 추가**를 먼저 구현한다. 추천 결과에는 검색어와 다음 행동을 포함한다.
2. **공급처 캡처 시 추천 메시지 선택**을 추가하여 `ref_ids`를 자동 연결한다.
3. **네이버 조사 메시지에 공급처 후보 연결**을 추가한다.
4. **검증방 체크리스트**를 추가하여 원가·마진·경쟁·위험을 구조화한다.
5. **통과·보류·반려 결정**을 append-only 결정 메시지로 구현한다.
6. **콘텐츠제작방 또는 콘텐츠 제작 메시지 유형**을 추가한다.
7. **상품명·썸네일·이미지 결과물의 저장 계약**을 정한다.
8. **최종 승인 이후 판매 시작 기록**을 추가한다.
9. 외부 쇼핑몰 자동 등록은 위 단계가 안정화된 뒤 별도로 설계한다.

## 10. 변경하지 말아야 할 원칙

- AI 추천만으로 승인하지 않는다.
- 네이버 검색 결과만으로 동일상품을 확정하지 않는다.
- 기존 원문 메시지를 수정하거나 삭제하지 않는다.
- 방별로 상품 원문을 복제하지 않는다.
- 로그인 자격증명을 저장하지 않는다.
- 외부 쇼핑몰 등록은 사용자의 명시적 실행과 최종 확인 없이 자동화하지 않는다.
- 콘텐츠 생성 결과와 판매 승인을 같은 상태로 취급하지 않는다.

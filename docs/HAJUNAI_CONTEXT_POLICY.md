# HajunAI 컨텍스트 판정 정책

> 기준 브랜치: `master`  
> 적용일: 2026-09-08

## 목적

HajunAI가 과거 상태 요약을 현재 사실로 재사용하거나, 사람이 확인하지 않은 AI 답변을 확정된 결정으로 취급하지 않도록 컨텍스트의 출처와 우선순위를 고정한다.

## 현재 상태 판정 우선순위

현재 상태는 다음 순서로 판정한다.

1. 현재 `master` 코드와 실제 배포 응답
2. 최신 시각이 기록된 HajunAI 방 원문
3. 확인된 API 응답과 사람 확인 결정
4. `dev_contexts`와 기타 파생 요약
5. 기준일이 지난 Step 3·CoreRing·번역·음성 상태 요약

오래된 요약과 최신 방 원문이 충돌하면 최신 원문을 우선한다. 다만 최신 원문에도 기록 시각이 없으면 현재 사실로 단정하지 않고 검증 필요로 표시한다.

## 상태 분류

| 분류 | 처리 원칙 |
|---|---|
| 현재 구현 | 코드와 배포 응답으로 확인된 기능 |
| 확인된 결정 | 사람이 확인했음을 나타내는 기록만 포함 |
| 검토 대기 | AI가 생성했거나 `adopted` 상태인 기록 |
| 역사 기록 | 과거 기준일의 상태 요약. 삭제하지 않고 현재 판정에서 낮은 우선순위로 취급 |
| 검증 필요 | 데이터베이스·외부 서비스의 현재 상태를 직접 확인하지 못한 주장 |

## 폐기 API

`context_package`는 폐기된 경로다. 호환 호출은 폐기 안내만 반환하며, 현재 컨텍스트를 제공하는 API로 설명하지 않는다.

에이전트 계약·원칙·로드맵은 다음 명시적 문서 API를 사용한다.

```text
GET /api/docs?agent=clo2
GET /api/docs?agent=clo3
GET /api/docs?agent=pm
```

하준아이 방 원문은 다음 API를 사용한다.

```text
GET /api/hajun?action=view_room&room_id=...
```

## AI 답변 상태

AI 답변은 생성 직후 확정 결정이 아니다.

```text
AI 생성 답변 → adopted 또는 검토 대기 → 사람 확인 → confirmed
```

`confirmed_by_human=true`가 없는 AI 답변은 확정된 사실이나 프로젝트 결정으로 말하지 않는다. 기존 기록을 삭제하거나 덮어쓰지 않고, 확인·정정 행위는 새 기록으로 남긴다.

## 마당 공유 원칙

관제마당·개발마당·브라이언풀마당은 자동 피드 병합하지 않는다. 하준챗 호출이나 확장 프로그램의 방 주입처럼 사용자가 명시적으로 요청한 경우에만 필요한 마당·방 기록을 조회한다. `ref_ids`는 사용자가 지정한 근거 관계를 보존하며, AI가 읽은 최근 기록 전체를 자동 근거로 승격하지 않는다.

## 외부 AI 주입

URL을 직접 읽지 못하는 외부 AI에는 브라이언풀 확장 프로그램이 사용자가 선택한 방의 맥락을 텍스트로 입력창에 주입한다. 자동 전송하지 않으며, 사용자가 내용을 확인한 뒤 직접 전송한다.

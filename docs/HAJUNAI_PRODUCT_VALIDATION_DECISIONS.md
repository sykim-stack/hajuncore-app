# HajunAI 상품검증 MVP 결정 문서

> **상태:** 1차 범위 확정 / 구현 전
> **갱신일:** 2026-09-09
> **협업 담당:** Manus 1·Manus 2

## 확정 사항

상품검증은 기존 HajunAI의 `마당 → 거실 → 방` 흐름으로 구현한다. 상품검증마당과 기능별 방을 사용하되, 상품별로 방을 만들지 않는다.

기존 엔진방의 `hajun_posts`는 당분간 참고 자료로 읽을 수 있다. 그러나 상품검증의 공식 원본이나 신규 저장소로 사용하지 않는다. 상품 원문과 검증 이력은 `hajun_messages`에 저장한다.

```text
온채널·네이버 원문 → hajun_messages 1회 저장
AI 분석 → 새 hajun_messages + 원문 ref_ids
사람 확정 → 새 decision 메시지
```

같은 상품을 다시 캡처하거나 조사하는 것은 허용한다. 이것은 상품 원문 복제가 아니라 시간순 검증 이력이다. 동일 원문을 `hajun_messages`와 `hajun_posts`에 동시에 복제하는 것은 금지한다.

## 중복 판정

상품 식별자는 다음을 우선 사용한다.

```text
internal_code = source + ":" + source_product_code
```

상품명만으로 동일상품을 확정하지 않는다. 랜덤 검증은 기존 후보 메시지를 `internal_code`별로 묶어 하나를 선택하고, 선택 결과는 원본 메시지 ID를 `ref_ids`로 연결한다. 랜덤 선택을 위해 상품 복사본을 만들지 않는다.

## 최소 검증 흐름

```text
상품 캡처
→ internal_code 확인
→ 기존 후보 검색
→ 중복이면 기존 기록 표시
→ 신규면 상품발굴방에 hajun_messages 저장
→ 시장조사 메시지를 같은 internal_code로 연결
→ 원문 ref_ids 기반 AI 분석
→ 사람 확인 전 검토 대기
→ 사람 확정 시 decision 기록
```

## 이번 단계의 범위

- 마당·거실·방 기본 동작
- 상품 후보 메시지 조회
- internal_code 중복 확인
- 원문 저장과 ref_ids 연결
- 기본 검증·분석 로직
- 위 흐름의 자동화 테스트

## 이번 단계에서 제외

- 별도 `products` 중심 데이터 모델
- 상품별 방 자동 생성
- `hajun_posts` 신규 쓰기
- 카페24 자동 등록
- CoreHub 자동 이관
- AI 분석만으로 판매 승인
- 네이버 결과의 동일상품 자동 확정
- 대량 자동 수집과 자동 로그인

## 미결 사항: 구현 전 확인

| 항목 | 상태 |
|---|---|
| 실제 상품검증마당·방 key | 기존 DB 확인 후 확정 |
| `hajun_messages` 실제 컬럼 | DB 확인 필요 |
| `metadata jsonb` 지원 여부 | DB 확인 필요 |
| `adopted/confirmed` 저장 방식 | 스키마·API 설계 필요 |
| CoreHub 이관 payload | 본 MVP 이후 결정 |
| 온채널·네이버 추출기 | API 계약 테스트 후 구현 |

## 인수인계 주의사항

Manus 1 또는 Manus 2가 작업을 이어받을 때는 루트의 `HANDOFF.md`를 먼저 읽는다. `master`만 기준으로 작업하며, 상품검증 구현 전에 DB 컬럼과 기존 key를 확인한다. 설계가 미결인 상태에서 새 테이블·새 원본·자동 승인 흐름을 추가하지 않는다.
